# نظام حضور الطلاب — المركز + تطبيق المعلم

نظام حضور مدرسي عربي (RTL) يعمل **بدون خادم وبدون مزامنة**. يتكوّن من تطبيقين مستقلين يتشاركان الكود نفسه:

| الجزء | المجلد | الوظيفة |
| --- | --- | --- |
| **المركز** | `center/` | الطلاب، المعلمون، الجدول الأسبوعي، استيراد ملفات الغياب، التقارير، تصدير حزم المعلمين، النسخ الاحتياطي، قفل PIN. يعمل بالنقر المزدوج من `file://` أو من استضافة ثابتة. |
| **تطبيق المعلم** | `teacher/` | PWA للموبايل: إعداد أول مرة، «حصصي اليوم»، مسح الباركود، حفظ الجلسة، تصدير ملف الغياب. يعمل أوفلاين بعد أول تحميل. |
| **المشترك** | `shared/` | `core.js` (المنطق النقي والصيغ) و`base.css` (المتغيرات والأنماط الأساسية). |
| **المكتبات** | `vendor/` | ZXing وXLSX وJSZip وخط IBM Plex Sans Arabic، بنسخ محلية ثابتة بلا CDN. |
| **Service Worker** | `sw.js` | في **جذر المشروع** ليغطي `teacher/` و`shared/` و`vendor/`. لا يخزّن `center/`. |

---

## 1) التشغيل السريع

### المركز

افتح الملف مباشرة:

```text
center/index.html
```

يعمل من `file://` بكل الوظائف (الاستيراد/التصدير والملصقات)، ولا يحتاج خادمًا. للتحقق من ذلك آليًا راجع `NOTES.md` (T12).

بديل عبر خادم محلي (مفيد إن أردت فتح المركز والمعلم من نفس العنوان):

```bash
python -m http.server 8080
# أو
npx serve .
```

ثم:

```text
http://localhost:8080/center/
```

### تطبيق المعلم

يحتاج **HTTPS** أو `localhost`، لأن الكاميرا والـ Service Worker لا يعملان على `file://`:

```text
http://localhost:8080/teacher/
```

على الهاتف، انشر مجلد المشروع على أي استضافة ثابتة تدعم HTTPS (GitHub Pages، Netlify، خادم المدرسة…)، ثم افتح:

```text
https://<موقعك>/teacher/
```

> **مهم عند النشر:** يجب أن يبقى `sw.js` في **جذر الموقع**، بجانب مجلدات `teacher/` و`shared/` و`vendor/`، لا داخل `teacher/`؛ وإلا لن يعمل التطبيق أوفلاين ولن تُخزَّن ملفات `shared/` و`vendor/`.
>
> **عند تحديث أي ملف من `teacher/` أو `shared/` أو `vendor/`:** ارفع قيمة `BUILD` داخل `sw.js`. بدون ذلك سيستمر المتصفح في تقديم النسخة القديمة من الكاش (cache-first).

### تثبيت التطبيق على الهاتف

- **Android/Chrome:** يظهر زر «تثبيت التطبيق» عند دعم المتصفح، أو من قائمة المتصفح ← «تثبيت التطبيق».
- **iOS/Safari:** زر المشاركة ← «إضافة إلى الشاشة الرئيسية».
- بعد التثبيت افتح التطبيق مرة واحدة وأنت متصل لتخزين كل الملفات، ثم يعمل بدون إنترنت.

## 2) سير العمل الكامل

1. **في المركز:** أضف الطلاب (يدويًا أو من Excel/CSV)، ثم أضف المعلمين وحصصهم في الجدول الأسبوعي.
2. **صدّر حزمة المعلم:** من قسم «المعلمون» اضغط زر «حزمة» أمام المعلم، أو «تصدير حزمة المعلم المحدد»، أو «تصدير كل الحزم (ZIP)».
3. **في تطبيق المعلم:** عند أول تشغيل اختر ملف الحزمة `.json`، راجع البيانات، أكمل الإعداد، ثم ابدأ الاستخدام. لتحديث الحزمة لاحقًا: الإعدادات ← «استيراد حزمة جديدة».
4. **الحصة:** من «حصصي اليوم» اضغط بطاقة الحصة، امسح الباركود أو أدخل الكود يدويًا، ثم «إنهاء وإرسال». يُنزَّل ملف `ATT-ABSENCE` بصيغة Excel.
5. **في المركز:** قسم «الوارد» ← اختر ملف الغياب ليظهر «مقبول»، وتتلوّن الخلية في لوحة اليوم.

### تصدير الحزم

- الحزمة تحتوي **فصول المعلم وطلابه وجدوله وإعدادات المدرسة فقط**، وليست بيانات المدرسة كلها.
- تُستبعد الحصص التي لا طلاب لفصلها تلقائيًا حتى تبقى الحزمة صالحة.
- ملف الحزمة: `PACK_<اسم المعلم>_<التاريخ>.json`.
- ملف ZIP لكل المعلمين: `PACKS_<التاريخ>.zip`.

### ملفات الغياب والاستيراد

- اسم ملف الغياب: `ABS_<التاريخ>_P<الحصة>_<الصف>-<الفصل>.xlsx`.
- إعادة تصدير **نفس المحتوى** تعيد نفس `fileId`، فيعتبره المركز «متجاهلًا» (مكررًا).
- تعديل الجلسة أو إعادة فتحها ثم التصدير يُولّد `fileId` جديدًا، فيظهر في المركز «مستبدَل».
- ملفات `ATT-ABSENCE` الإصدار 1 القديمة تبقى مقبولة.

## 3) البيانات والنسخ الاحتياطي

كل البيانات محلية في `localStorage` ولا تُرسل لأي خادم:

| المفتاح | المحتوى |
| --- | --- |
| `attendance_center_v3` | بيانات المركز (طلاب، معلمون، جدول، وارد، سجلات، إعدادات، PIN). |
| `attendance_teacher_v1` | حزمة المعلم وجلساته وتفضيلات جهازه. |
| `attendance_app_v2` | بيانات النسخة القديمة، تُرحَّل تلقائيًا عند أول فتح للمركز ولا تُحذف. |
| `attendance_app_v2_backup_migrated` | نسخة احتياطية خام من بيانات النسخة القديمة. |

- **نسخة احتياطية:** الإعدادات ← «تنزيل نسخة احتياطية (JSON)». والاستعادة من الزر المجاور بعد تأكيد.
- **قفل PIN:** من الإعدادات، من 4 إلى 8 أرقام. يُطلب عند فتح المركز وبعد خمول 1–60 دقيقة، وعند العمليات الحساسة (حذف البيانات/السجلات، استعادة نسخة، تغيير PIN). بعد 5 محاولات خاطئة يتفعّل انتظار 30 ثانية يتضاعف مع كل دفعة.
- **نسيان PIN:** «إعادة ضبط المركز» من شاشة القفل تمسح بيانات المركز نهائيًا بعد كتابة عبارة التأكيد؛ استعد نسخة JSON بعدها.
- **حدود الأمان:** قفل PIN حماية واجهة ضد الاستخدام العرضي فقط، وليس تشفيرًا؛ من يملك أدوات المطور أو يستطيع قراءة تخزين المتصفح يمكنه تجاوزه. احمِ جهازك بحساب نظام وقفل شاشة.

## 4) الاختبارات

```bash
node --test tests/
```

- 55 اختبار وحدة: صيغ الملفات والـ checksum، `validatePack`/`buildPack`، حصص اليوم، `fileId` وإعادة التصدير، الترحيل من v2، PIN، وسلوك الـ Service Worker.
- لا حاجة إلى `npm install` ولا خطوة بناء.

تفاصيل التحقق اليدوي في المتصفح، وما لم يُختبر ولِماذا: `NOTES.md`. وقائمة معايير القبول وحالتها: `DELIVERY.md`.

## 5) المتطلبات والحدود المعروفة

- **المتصفح:** Chrome أو Edge حديثان (سطح المكتب وAndroid)، وSafari حديث على iOS. يلزم `crypto.subtle` لـ PBKDF2، مع بديل SHA-256 مكتوب بـ JavaScript.
- **بدون CDN:** تطبيق المعلم لا يحمّل أي أصل خارجي؛ كل المكتبات والخطوط من `vendor/`.
- **بدون خادم أو مزامنة:** نقل البيانات يتم بملفات الحزمة وملفات الغياب والنسخ الاحتياطية فقط.
- **حدود التخزين:** `localStorage` سعته نحو 5MB؛ استخدم زر النسخ الاحتياطي دوريًا، خصوصًا قبل تنظيف بيانات المتصفح.
- **`xlsx@0.18.5`:** إصدار مثبّت في الخطة وله تنبيهات أمنية معروفة عند قراءة ملفات غير موثوقة؛ لا تستورد ملفات من مصادر مجهولة.
- **iOS:** قد يحذف المتصفح بيانات المواقع غير المثبّتة بعد فترة؛ ثبّت التطبيق واسمح بالتخزين الدائم إن طُلب.
- **الكاميرا:** تتطلب سياقًا آمنًا (HTTPS أو `localhost`) وإذنًا من المستخدم.

## 6) الوثائق

- `WORK_PLAN.md` — المتطلبات ومعايير القبول الأصلية.
- `NOTES.md` — قرارات التنفيذ، الإصدارات، الاستثناءات، وما لم يُختبر.
- `DELIVERY.md` — تقرير التسليم وحالة كل معيار قبول.
- `AGENTS.md` — القواعد الملزمة للعمل على المشروع.


## النشر على GitHub Pages

1. أنشئ مستودعًا عامًا على GitHub وارفع الفرع main (الجذر).
2. في المستودع: **Settings → Pages → Build and deployment → Source: Deploy from a branch**، واختر main و/ (root)، ثم Save.
3. انتظر دقيقة، ثم افتح:
   - https://<user>.github.io/<repo>/ (صفحة الدخول)
   - https://<user>.github.io/<repo>/teacher/
   - https://<user>.github.io/<repo>/center/
4. إصدار تحديث: عدّل BUILD في sw.js (مثلاً 2026-10-30.1)، ثم commit وpush. بعد ~دقيقة أعد تحميل صفحة المعلم (شريط التحديث يظهر) وانقر «تحديث الآن».
5. .nojekyll موجود لتفادي معالجة Jekyll؛ .gitignore يمنع رفع بيانات تجريبية.
